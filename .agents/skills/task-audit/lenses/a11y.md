# Lens: accessibility (WCAG 2.2 AA, templates and their TypeScript)

Every app targets WCAG 2.2 AA (`documentation/accessibility.md`). Users reach the eco apps by keyboard, screen reader and touch: phones are the main device of eco-store.

## Already mechanical (input, not work)

ESLint's template accessibility rules, all errors (`documentation/code-style.md` «Templates and accessibility»): `alt-text`, `label-has-associated-control`, `interactive-supports-focus`, `click-events-have-key-events`, `no-positive-tabindex`, `no-autofocus`, `valid-aria`, `role-has-required-aria`, `table-scope`, `button-has-type` and the rest of angular-eslint's accessibility preset. Pa11y runs in the pre-push on built pages (eco-store) with the 2.1 AA rule sets plus axe's `target-size`; it sees the rendered DOM, not the states a page only reaches after an action.

## Judgement checks

1. **Accessible names in every state.** Icon-only buttons have a translated `aria-label` that changes with the state it toggles (show/hide password, theme); a decorative `mat-icon` is `aria-hidden="true"`; an image that carries meaning has real alt text.
2. **Focus.** After an error, the message or the first invalid field takes the focus; a dialog focuses its first meaningful control, is labelled by its title and returns the focus on close; a route change lands on `main` or the page heading. Nothing removes the visible focus ring. 2.4.11: a sticky element (the floating header) never hides the focused control.
3. **States announced.** Loading, success, error and empty states use `aria-live` or `role="status"`/`role="alert"`, and the live region exists before its content appears (one added with its content is often not read).
4. **Forms.** Each error is tied to its control (`mat-error`, `aria-describedby`); required is conveyed; `autocomplete` holds a token valid for the input's `type` (Pa11y's HTML_CodeSniffer rejects `username` on `type="email"`, 1.3.5). 3.3.7: data the user already gave is not asked again in the same flow. 3.3.8: login allows paste and password managers and asks no cognitive test.
5. **Keyboard parity.** Whatever a pointer can do (drag, hover, double-click, swipe) has a keyboard path; 2.5.7: dragging has a single-pointer alternative.
6. **Target size.** 2.5.8: targets at least 24×24 CSS px or spaced so; eco-admin's design brief asks 44×44 inside the shell.
7. **Structure.** One `h1` per view, heading levels without gaps, landmarks (`main`, `nav`, `header`) intact after the change.
8. **Colour and motion.** Status is never colour alone; non-essential animation (shake, transitions) stops under `prefers-reduced-motion`.

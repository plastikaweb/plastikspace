## The prompt

You are designing **Eco Admin**, the internal administration app for a multi-tenant e-commerce platform serving ecological consumer cooperatives in Catalonia. Cooperative operators (volunteers, not tech professionals) use it weekly to manage products, orders, weekly order cycles, members and store configuration. A second role (platform superadmin) manages the cooperatives themselves.

This is **NOT a greenfield design**. A production design system already exists — brand "Organic and Kind": natural, light, welcoming; Material 3; OKLCH-derived palettes; Manrope. Your job is to **extend it with an admin-density layer**, not to invent a new one. Every token below is law: do not introduce new colors, fonts, radii or spacing values. Where you need something the tokens don't provide, derive it from them and flag it explicitly as a proposal.

### 1 · Constraints (hard)

- **Component vocabulary: Angular Material 3.** Every component you draw must map to a Material component (`mat-table`, `mat-chip`, `mat-sidenav`, `mat-card`, `mat-button-toggle`, stepper, datepicker…) or be an explicit composite of them. Name the mapping in annotations.
- **Light AND dark** for every key view. The system uses CSS `light-dark()`; both modes ship day 1. There is also a `prefers-contrast: more` variant — you don't need to design it, but avoid patterns that would break under a higher-contrast palette (no meaning carried by subtle tints alone).
- **WCAG 2.1 AA**: contrast, focus states visible, no color-only status encoding (icon or text label always accompanies). **Touch targets ≥ 44px on mobile breakpoints is a house rule, not WCAG AA** — WCAG 2.1's 44×44 (2.5.5) is Level AAA and the AA criterion is WCAG 2.2's 2.5.8 at 24×24; we hold the stricter bar deliberately.
- **UI copy in Catalan.** Section names: Tauler (dashboard), Sol·licituds (requests), Socis (members), Comandes (orders), Cicles (cycles), Productes, Categories, Botiga (store settings), Cooperatives (tenants, superadmin only).
- **Desktop-first** (1280+), functional at tablet; mobile only needs: dashboard, requests inbox, store open/close.
- **Operator copy is copy** (added 2026-08-18 after five review rounds of the same finding): no requirement IDs (`AREQ-07`), HTTP codes (`409`), schema names or implementation terms (`hook`, `Batch API`, `transacció`, `hard delete`, `user → null`) in operator-facing text. Mock-only annotations (open decisions, "pending AQ-10") live exclusively in the SPEC block of the mock, tagged as such. Confirm dialogs and error states must state only what the operator can act on — and never promise a communication (email, notification) that the backend does not send.

### 3 · What to deliver — part A: the admin-density extension spec

The storefront is airy and generous; the admin needs **data density without losing the organic warmth** (warmth lives in: surface tint layering, 16px card radius, pill accents, Manrope, generous section spacing — NOT in bloated row heights). Specify as tokens + component specs:

1. **Density scale**: table row heights (comfortable ≈48px / dense ≈40px — **one app-level user preference stored with the user's prefs, never a per-table control**), form-field height **40px desktop default / 44px on touch breakpoints** (name the `mat-form-field` density level for each; Angular Material steps 4px from 56, so 44 ≈ −3 and 40 ≈ −4 — verify before pinning), list paddings — expressed with the `--space-*` scale. Pin the **height inventory** too: chips 24 (status) / 32 (interactive), buttons 40 / 36 / 32 with their `mat-button` density, and list every M3 deviation (top bar 56 vs 64, rail 72 vs 80, drawer 256 vs 360, chip 24 vs 32) explicitly as density deltas.
2. **Data table pattern** (`mat-table` base): header treatment on `surface-container`, sorted-column affordance, row hover/selected states (use state-layer opacities), sticky first/action columns, inline-edit cell state, pagination bar, bulk-selection bar that appears on selection, empty state, loading state. Hover/selected state layers must propagate to the sticky cells (opaque background, same tint). Name the row-tint tokens generically (`--admin-row-warn-bg` / `--admin-row-error-bg`) — the RGPD escalation and CSV error rows both consume them.
3. **Filter bar pattern**: search input + chips/selects row above tables; collapsed→expanded on tablet. **Round 12 — one chip anatomy and a two-pattern rule:** selected chip = secondary-container fill + leading check, inactive = outlined, live «· N» counts from the same query as the rows; search always **left** (300px), chips after, actions right; a second filter axis sits after a 1px outline-variant separator; chips carry `aria-pressed`. **KPI stat-cards double as filters (DS §18) only when** the set is a bounded pipeline (≤ 7 states) with an operationally meaningful aggregate (count + €) on a page scoped to one container — Comandes only — round 14 overturned Cicles' candidacy (near-singleton states, no per-state aggregate, page spans history: an anti-example); entity lists (Socis, Productes) and the Cicles list always use §05 (or nothing). Sol·licituds' right-hand search was a recorded deviation (frozen 4.1g) — **corrected in round 27** (search left, §05). **Round 27 — sections vs chips:** when a tray's filter axis separates **jobs** — values with different lifecycles, sort keys or row grammars (`ACCOUNT_DELETION`'s statutory clock vs `SIGNUP`'s approval) — it renders as **fixed sections** with sticky counted headers, never as filter chips: filters are retrieval machinery, sections are an order of work. Chips remain for retrieval over homogeneous rows, and the two rules compose (Lliuraments runs chips _inside_ its job-sections). An empty section disappears; an all-empty queue shows its success state. **Amendment 12.1 — reset de filtres:** one M3 text button «Neteja els filtres» (`filter_alt_off`, 32px) at the right end of the bar, rendered **only** when filter state differs from the default; it clears search + chips + second axis + KPI selection and returns pagination to page 1 — never sort, density, column preferences, or the Sol·licituds tray tabs; on activation focus returns to the search input; the filtered-empty state offers the same reset as its primary action.
4. **Status chip system** — the platform's state machines, each chip = color + icon + Catalan label (never color alone):
   - Cycle: `DRAFT` (neutral) · `OPEN` (success) · `PROCESSING` (info) · `COMPLETED` (primary) · `CLOSED` (neutral-dark)
   - Order: `PENDING` · `CONFIRMED` · `PREPARING` · `READY` · `DELIVERED` · `CANCELLED` · `EXPIRED` (map across warning/info/primary/success/neutral/error). **`PAID` is NOT part of this family** — AQ-07 treats `orders.status = PAID` as legacy and drives payment through `paymentStatus`; defining it in both families produces two identical chips on the same row.
   - Payment: `UNPAID` (warning) · `PAID` (success) · `REFUNDED` (info) · `FAILED` (error) — **visually distinct from the Order family** (outlined variant, leading `€` glyph): both families share an order row and `PENDING` + `UNPAID` must never read as two identical warning chips
   - Membership: `TRIAL` (info) · `ACTIVE` (success) · `INACTIVE` (neutral) · `SUSPENDED` (error)
   - Request: `PENDING` (warning) · `PROCESSED` (success) · `DISMISSED` (neutral) — plus the **derived** resolution labels used in the Resolts tray (not status values, never an enum): `Processada` (success) · `Descartada`/`Descartat` (neutral) · `Executada` (info — `ACCOUNT_DELETION` + `PROCESSED`) · `Respost` (success — `CONTACT` + `PROCESSED`)
   - Allowlist: `PENDING` (info) · `CONSUMED` (success) · `REVOKED` (error)
5. **Deadline indicator**: RGPD countdown for deletion requests (~30-day statutory clock): normal → warning ≥14 days elapsed → critical ≥21 days. Design the escalation (chip/badge + inbox row treatment + dashboard card). **Always present on `ACCOUNT_DELETION` rows** (neutral shows "Queden N dies", never a bare age). **Post-reply lifecycle** (REQUIREMENTS AREQ-09, frozen in design round 4.1g): once a reply is recorded the chip becomes `Bloquejada fins <data>` (neutral) → `Data prevista superada` (warning) → `Llesta per executar` (primary) → `Executada` (info); replied requests leave the dashboard's urgent count.
6. **Destructive-action confirm** dialog pattern: consequence text, typed/checkbox acknowledgment for cascade deletes ("this deletes N products"), pill buttons, error-container accents.
7. **i18n field editor**: pattern for JSON `{ca, es, en}` text fields — language tabs or stacked inputs, showing only the tenant's active languages; include the rich-text variant (aboutUs) and the per-language completeness indicator.
8. **Form layout**: 2-column desktop forms with section cards, sticky save bar with dirty-state, inline validation (Catalan messages).
9. **CSV import stepper**: upload → validated preview (per-row ok/error) → commit report. (Member allowlist bulk import.)
10. **App shell**: left `mat-sidenav` (collapsible to icons) + top bar. Top bar: breadcrumbs, global search (future), theme toggle, user menu. **Tenant Admin sees**: Tauler, Sol·licituds (with pending-count badge), Socis, Comandes, Cicles, Productes, Categories, Botiga, Estadístiques. **Superadmin sees**: Cooperatives, Catàlegs globals, Idiomes — opening a cooperative opens its **fitxa** — a read-only record summary whose only actions are Suspèn/Reactiva and TA-account recovery (edits only during Onboarding; everything else is the tenant admin's, in Botiga), never the tenant's own admin; no context selector and no member-derived figures at this layer (§2.2, round 17.2). Include the store-status indicator (open/closed) always visible for TA.
11. **Categorical dataviz tokens** (added 2026-08-12, dashboard critique): chart series representing product categories use each category's own `product_categories.color` (schema field), contrast-adjusted per theme to ≥3:1 against its surface — **never** the status palettes (success/info/warning/error/neutral stay reserved for states). Because `color` is tenant-editable free text, the system needs a robustness rule: pairwise-distinguishability check between active series (incl. deutan/protan simulation) with a fallback tonal ramp (primary steps) when colors are missing or clash. Single-series charts: `primary-400` minimum on light surfaces, `primary-600` for emphasis/selected. Every chart ships an accessible data-table toggle and keyboard-reachable values.
12. **Derived-value rules** (pin them so mocks and build agree): cycle countdown = `endsAt − now`; cycle progress = `(now − startsAt) / (endsAt − startsAt)`, labeled "temps transcorregut · N%" and wired to `role="progressbar"`; chart series must reconcile with the KPIs shown beside them and the y-axis ceiling must cover the max value; RGPD deadline chip shows **remaining** days ("Queden N dies") while escalation is computed on **elapsed** days of the ~30-day clock: neutral < 14 → warning ≥ 14 → critical ≥ 21 (critical: chip error-fill; only the requests card takes error-container emphasis; any pulse animation respects `prefers-reduced-motion`).
13. **Detail surfaces — decision rule** (added 2026-08-22, design round 5): one rule, not one surface. **Side sheet (modal, right)** for triage queues where the list must stay visible, detail fits one viewport and carries ≤ 3 actions — Sol·licituds (frozen 4.1g). **Route page** for entities with identity and history, more than one viewport, forms with a save bar, printables, cross-module links — Socis, Comandes, Cicles, Productes. **Dialog** only for decisions (confirm, reply, reason) — never as detail. **Inline row expansion** only for a single read-only tier (items snapshot, CSV error reason) — never actions, never in tables with sticky columns. **Bottom sheet** is the mobile render of the side sheet (≤ 720), not a desktop surface. No persistent split pane (1180px tables cannot share a 1280 viewport). Side-sheet spec: `mat-sidenav position="end" mode="over"` (or CDK `Dialog` with slide), 420px / `max-width: calc(100vw − 4rem)`, scrim on-surface 30 % (45 % dark), `surface-container-lowest`, level2, 220ms emphasized-decelerate in (none under reduced-motion); header = icon · title (title-medium) · status chip · close; scrollable body; sticky action footer; Esc closes, focus trapped and returned to the originating row, "Anterior / Següent" without closing; **state lives in the URL** (`/sol-licituds/:id` child route rendering the sheet over the same list) so Tauler deep links and reload work.
14. **Focus & feedback** (added 2026-08-22, design round 5): every non-Material composite (clickable list rows, chip-menus, sticky cells, language pills, stepper steps) gets a visible `:focus-visible` ring — 2px primary, 2px offset, the component's own corner. Snackbar + **Desfés** maps to `mat-snack-bar` (bottom-centre, ~6 s, live region; the side effect runs when the snackbar closes, never before). Specify the **conflict state** ("Algú s'hi ha avançat" + Actualitza — no HTTP code), a generic error banner and the 403 state alongside empty/loading. `prefers-reduced-motion` is a rule of the sheet itself, not only of the views.

    **Table accessibility contract** (added 2026-08-22, design round 8 — measured: the Socis and Sol·licituds views shipped with **zero** ARIA attributes while the Tauler had nine, because only the Tauler had been reviewed for it). Every list view must ship, and every review must check: sortable headers as `<button>` carrying `aria-sort`; row and header checkboxes with an accessible name naming the row ("Selecciona Marta Puig", "Selecciona-ho tot"); any chip that opens a menu with `aria-haspopup` + `aria-expanded`, a real `role="menu"`, arrow/Esc keys and focus returned to the trigger; overflow (`⋮`) buttons with a name **and a wired menu**; pagination controls as focusable buttons, never `<span>`; decorative avatar initials `aria-hidden="true"`; dialogs with `role="dialog"`, `aria-modal="true"`, **an accessible name** (`aria-label` or `aria-labelledby` on the title), Esc, a focus trap and focus returned to the trigger; filter chips exposing `aria-pressed`; destructive icon actions with a visible label or a menu, a ≥44px target and the §3.6 confirm. Icon-only controls never rely on `title` alone.

    **i18n fields** (round 18, amended 18.1 — one grammar; the platform caps languages at 3, so stacking is cheap). The i18n unit is **always the language row**: a stack of labelled rows, CA (base) first, a language-chip prefix, per-row inline validation, the empty-falls-back-to-CA note visible. Short fields: the row is the input. **Long fields: the same rows with auto-height textareas — no tabs anywhere in the i18n system.** The only collapse case is a rich editor (future aboutUs): same row grammar, collapsed rows show a one-line preview + textual state («ES — buit» — never color alone) and expand in place; saving with an invalid language expands and focuses the first invalid row. Canonical drawing: DS §09.

    **Save bar** (added 2026-08-26, design round 19). Route forms have one save anatomy — the sticky bottom bar — with two modes: **create** = always visible (create-language status text, or an invalid hint naming the missing fields; primary CTA «Crea …» with `aria-disabled` while invalid) and **edit** = appears on dirty («Canvis sense desar» + Descarta-revert + «Desa els canvis»). Dialogs keep footer buttons — a different surface. Reference implementation: the tenant Categories form.

    **Row-action grammar** (added 2026-08-25, design round 13 — measured: six lists had five different ways to reach the row's detail and four different action affordances; the rule lives in DS §04 «Accions de fila»). The row's **identity cell (name, code) is always the link** to its detail or form when one exists — the canonical way in; card-lists (Sol·licituds) keep the full-row click with a passive chevron instead, because they are queues, not tables. Actions follow a ladder: none → passive marker with `aria-label` (the Categories lock); the module's **operational verbs** → always visible and labelled (Comandes «Confirma ›», Llista blanca Revoca/Restaura); **edit/delete only** → the direct icon pair `stylus` + `delete`, in that order, each with `aria-label` + `title`; **3+ or rare/dangerous actions** → a ⋮ menu with the full Socis kit (`aria-haspopup`/`aria-expanded`/named trigger, `role="menu"`, arrows + Home/End + Esc + focus return, 44px). A ⋮ may keep «Obre …» as its first item as a shortcut. `chevron_right` is a passive glyph on card rows or part of a labelled button — never a bare icon-link in a table cell. **Menu contents** (round 13.1): every menu item is a task named as a verb and earns its place by frequency or necessity; a single-item menu is acceptable only for a guarded escape hatch; destructive items go last, after a separator. One glyph per meaning — `stylus` is the project's edit glyph; variants of one glyph never mix. **Round 27.2 — markers vs verbs:** a row-leading **type marker** states what the row _is_ and draws from the domain family (`person`, `how_to_reg`, `person_off`, `mail`…); it may never reuse an action glyph (`delete`, `undo`, `stylus` and their variants are action-only anywhere in the admin) — a marker that looks like a verb turns a triage queue back into a button bar (measured: the safata's `delete`/`undo` type icons were read as row actions by the product owner).

    **Responsive bands & the Tauler card grid** (added 2026-08-29, design round 21). The Tauler card grid has three bands, measured on the **content pane's full (border-box) width** — the area right of the rail — never the viewport: **Ampla ≥1200** = the frozen layout (Cicle `2fr` + Comandes per estat `1fr`; «Requereix atenció» `1.15fr 1fr 1fr 1fr`; container max 1600); **Mitjana ≥720 and <1200** = 2 columns (`1fr 1fr`, gap 1.25rem) preserving the operativa/atenció zoning — Cicle full row, Comandes per estat full row, «Requereix atenció» as a 2×2 (Sol·licituds + Proves / Estoc + Socis); **Compacta <720** = the frozen mobile single column (§15 applies). Per-card rules: Sol·licituds keeps its emphasis variant (error-container only on a critical RGPD clock) and the block's first slot in Ampla/Mitjana; an orphan card on a multi-column row keeps its column width, never stretched (general rule for any card band — the Mitjana Tauler produces none); the closed-store banner always spans full width above the grid; every card declares `min-inline-size: 300px` and its internal layout responds to its own container. Build: container queries — `container-type: inline-size` on the pane **wrapper** with the 2rem padding on a child (queries resolve against the content box; padding on the container would shift every threshold by 60px). The system's mobile boundary stays 720 (§15/§16). Canonical drawing: DS §13 + the «Tauler — reflow» demo artifact (geometry only, no fixture data).

    **Operating modes & module-conditional nav** (added 2026-08-29, design round 22). A tenant runs in one of two modes: **window** (a weekly `orderWindow` generates cycles) or **continuous / 24-7** (`orderWindow.enabled` falsy — the cron skips it and cycles never exist; **B-31** proposes making this an explicit field instead of an absent JSON key). The mode is a TA setting, edited in Botiga › Logística (ACFG-02, AQ-19), never a GA one. Nav visibility follows a module's **domain**, not the mode flag (round 24 correction): Cicles appears when the tenant is in window mode **or** holds ≥1 cycle — historical cycles survive a mode switch and stay reachable read-only with a banner — and disappears only when the tenant is continuous _and_ has none. When it disappears the route is **guarded and redirects** (to Comandes, with a one-time explanation): a guarded route never renders, so there is no screen to design for it; the cycle zone of the Tauler is replaced by the frozen «Venda contínua» render — chip «Venda contínua», title «Comandes obertes», range «venda contínua · sense finestra setmanal», KPIs «N comandes obertes» + «N € aquests 7 dies», order scope «obertes ara»; the store chip reads «Oberta» with no closing time and the window-derived states collapse to open (ADSH-06); Estadístiques drops the cycle zone of its scope selector and keeps only dates. Three no-cycle states stay distinct and must never be conflated: «Cap cicle actiu» (window tenant between cycles, transient) · «Venda contínua» (continuous, structural) · «Sense cicles / Crea el primer» (window tenant, none created yet). Cardinality changes with the mode: the one-order-per-member rule is gated on the window being enabled, so a continuous tenant's member may hold several open orders at once — counts, batches and «socis han comprat» phrasing must not assume 1:1. Canonical drawing: the `24/7` scenario of the frozen Tauler.

    **Chart data views** (added 2026-08-29, design round 24). Every chart ships a data view (§3.11 a11y rule), but a table earns its place only by carrying what the chart cannot. Three rules: the toggle **swaps** the view, it never appends a table under a chart that already labels its bars — coexistence is what makes the table read as a transcription; the data view is a real `table` (caption, `th scope="col"`, right-aligned tabular figures) and not a list of rows; and it must add at least one column the chart lacks — the comparison against the previous period, the share of the total, or the running total — plus a total row. Zero-value periods, invisible as bars, are the data view's other reason to exist and are always listed («0 altes»).

    **Save bar — one primary at a time** (added 2026-08-26, design round 24; extends §3.16). When a route form also carries a workflow transition (order preparation being the case that forced this), the sticky bar shows exactly one primary: while dirty it is «Desa els canvis» (with Descarta), and only once clean does it become the transition CTA («Passa a "A punt"»). Advancing an entity's state with unsaved edits must be impossible, and the transition therefore lives in the bar next to the work — not in a far corner of the header, which keeps only the destructive action.

    **The order's two work surfaces** (added 2026-08-29, design round 25). An order is worked twice, by different people in different places, and the two moments need different surfaces. **Preparation** (desktop, at the table): the basket is the work, every line resolves to one of three visible outcomes — accepted as ordered (one tap), adjusted (editing the final quantity marks it reviewed), cancelled as unavailable (struck, out of the total, with an offered reason: preset chips plus free text, optional but pre-offered so giving one is nearly free). A header action resolves every untouched line at once, because a basket with nothing wrong must cost one tap. The transition is **gated on completeness** — «N de M productes revisats», CTA disabled until N = M — and once the order leaves preparation the controls vanish, the basket becomes a read-only summary of what will be charged (cancelled lines still visible with their reason, delta pinned) and the bar's primary becomes the next transition. **Delivery** (phone, at the door or the pickup point): not the order detail at all, but a day's run — grouped by delivery method, each row only what the courier needs, and two **independent** primary actions, «Lliurada» and «Pagada», because payment may happen before, during or after handover and neither may gate the other. Round 26 hardened the run's grammar: **state lives in chips, actions in buttons — never both in one control**; a finished row goes quiet (compact, success-tinted, sunk to its group's bottom) so the remaining work stays loud; the run takes the §05 filter bar (search + state/method chips, the header counters double as filters) and §15 load-more on both shells — a work queue never paginates pending work out of sight. **Status names are one per state across both apps** (eco-admin and the member storefront): a state that reads «A punt» to the admin and «Preparada» to the member is one fact with two names — perspective belongs in a sentence on the member's card, never in a different chip label.

### 5 · Output format

- Tokens for anything new: CSS custom properties following the existing naming (`--mat-sys-*` for M3 roles, `--space-*` for spacing, semantic palette steps for status colors). Deltas only — never restate the base system.
- Every screen annotated with: Material component mapping, spacing tokens used, type-scale tokens used, and the chip variants present.
- Anti-goals: no new fonts/colors/radii; no generic "SaaS admin" grey-blue look — this must feel like the same organic brand, denser; no glassmorphism (that's the storefront header's trick, don't copy it into the admin shell).
